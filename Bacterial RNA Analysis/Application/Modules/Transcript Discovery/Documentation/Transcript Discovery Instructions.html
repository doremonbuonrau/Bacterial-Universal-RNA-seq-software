Transcript Discovery - Instructions

Discover coverage-supported transcript segments, antisense transcripts, and candidate sRNAs from strand-specific bacterial RNA-seq evidence.

Purpose

This module segments strand-specific RNA-seq coverage and merges evidence across samples to propose transcript regions. It can classify novel intergenic and antisense transcripts, import optional Rockhopper evidence, run RNAfold for candidate sRNAs, and search Rfam with Infernal when the required database files are supplied.

Boundaries inferred from ordinary RNA-seq coverage are evidence-based candidates, not experimentally validated TSS or TTS positions.

Required inputs

  • RNA Processing result folder containing the reference, annotation, and strand-specific plus/minus coverage, or explicit overrides for those files.
  • Reference FASTA and matching GFF/GTF.
  • Strand-specific BigWig or bedGraph coverage. Unstranded coverage is insufficient for the intended transcript/antisense classification.
  • Results folder.

Optional input: a precomputed Rockhopper transcript table as independent supporting evidence.

Core parameters

ParameterMeaning
Minimum transcript lengthShortest coverage-supported segment retained.
Minimum sample supportNumber of libraries that must support a merged candidate when available.
Minimum coverage depthDepth threshold used by the native segmenter.
Maximum internal gapLow/zero-coverage gap that can still be bridged inside one segment.
Minimum antisense overlapMinimum opposite-strand overlap needed to report antisense evidence.

Optional RNA evidence

  • RNAfold: calculates folding evidence for candidate sRNAs when ViennaRNA is installed.
  • Infernal/Rfam: requires a user-supplied Rfam.cm and optional Rfam.clanin; the database is not bundled.

Recommended workflow

  1. Click Scan RNA Processing results folder and select the completed RNA Processing result tree. The scan searches recursively for the analysis folder, matching reference FASTA, GFF/GTF, strand-specific coverage, optional Rockhopper evidence, and reusable Rfam files.
  2. If you need to enter paths or optional Rockhopper rows yourself, click Manual Excel input. Pale examples are visible immediately inside empty cells; type or paste real values over them and choose Use data. Optional Excel export contains only editable input sheets.
  3. Review every assigned path and use an override only when it belongs to the same genome coordinate system.
  4. Keep conservative default segmentation parameters for the first run.
  5. Enable RNAfold/Rfam only when the required tools/data are available.
  6. Run, then review candidates in the workbook together with GFF3/BED and coverage in a genome browser. Checks, progress, and errors appear in the live console.

Outputs

The main workbook is Transcript discovery and architecture.xlsx. Other outputs include predicted_transcripts.tsv, antisense_transcripts.tsv, candidate_srna.tsv, transcript GFF3/BED, and FASTA files for predicted transcripts and candidate sRNAs.

Interpretation and troubleshooting

  • Require consistent strand-specific evidence and inspect candidates visually.
  • Low-depth or single-sample candidates should be treated as exploratory.
  • If no coverage is found, confirm that RNA Processing exported plus_transcript and minus_transcript tracks.
  • If FASTA/GFF contig names differ from coverage tracks, correct the reference mismatch before running.
