1. Overview

This operon module contains two different algorithms for predicting bacterial transcription units: rSeqTU and OpDetect.

rSeqTU was published on 15 May 2019 by Sheng-Yong Niu, Binqiang Liu, Qin Ma and Wen-Chi Chou. The article credits Niu with implementing the R package with Chou's help, and Niu, Ma and Chou with designing the study. The integrated Windows interface in Bacterial RNA Analysis was developed by Nguyen Hoang An and preserves the attribution of the original rSeqTU algorithm.

The rSeqTU Transcription Unit Predictor is embedded in the main Bacterial RNA Analysis interface. It accepts one aligned BAM file per run, validates the matching annotation and genome sequence, generates strand-specific coverage, runs the original feature-generation and SVM functions, and exports verified results in formats suitable for Excel and IGV.

Current integrated workflow: Open Bacterial RNA Analysis.exe, choose Operons and transcription units, and select rSeqTU. The rSeqTU workspace replaces the module chooser inside the same main window. Use < Back to operon methods to compare methods or < Back to analysis modules to return to the five-module dashboard. Do not launch or move the internal PowerShell and R files.

1.1 Main capabilities

  • Accepts one BAM file, a matching GFF, GFF3 or GTF annotation, a genomic FASTA file and a writable result folder.

  • Detects R automatically and installs missing CRAN or Bioconductor packages while skipping packages that are already available.

  • Creates a QuasR QC report, a bordered TU Excel workbook, a cleaned SVM GFF, a complete console log and an IGV Results subfolder. The final bedGraph, original annotation and original FASTA are always included. Select Copy BAM and BAI to IGV Results when a self-contained IGV folder with the alignment and index is desired.

  • Shows the exact R source, configuration and execution command in the live console and preserves the same complete trace in the persistent full console log.

  • Displays exact workflow-stage status and an estimated percentage, including the long SVM feature-selection stage.

  • Supports safe cancellation, protects the original BAM, GFF/GFF3 and FASTA files, resets the interface for the next sample, and keeps a session-only record of samples already run.

2. Scientific Basis and Published Scope

2.1 How rSeqTU predicts Transcription Units

The original rSeqTU method uses RNA-seq coverage continuity, gene-expression relationships and intergenic-region characteristics to distinguish neighbouring genes that are likely to be co-transcribed. The package applies random-forest-based feature selection within a machine-learning workflow and then uses an SVM model to generate Transcription Unit predictions.

Component Role in the workflow
Strand-specific coverage Provides the read-depth signal across genes and intergenic regions.
Genome annotation Defines gene order, coordinates and strand.
Feature matrices Summarize expression means, variability, gaps and fold-change relationships.
Random-forest selection Ranks informative features used by the predictive model.
SVM prediction Classifies adjacent same-strand relationships and builds final TU intervals.

2.2 Published performance and interpretation

The original authors reported near-98% accuracy in many tested cases, including public Escherichia coli RNA-seq datasets. This published value describes their evaluation setting; it is not a guaranteed accuracy for every organism, sequencing protocol, annotation or growth condition.

2.3 One sample per prediction run

Important: The original core functions receive one BAM-derived coverage file and one sample prefix at a time. This GUI therefore processes one BAM per run. Biological replicates should be run separately and compared afterward; the software does not fit a replicate-aware statistical model or automatically create a replicate consensus.

3. System Requirements and Installation

3.1 Recommended environment

  • A 64-bit Windows 10 or Windows 11 computer.

  • At least 8 GB RAM; more memory is helpful for large bacterial genomes and high-coverage BAM files.

  • Sufficient free disk space for the per-base coverage file and temporary feature matrices.

  • Internet access during the first run if R or packages must be installed.

  • Write permission for the selected result folder.

3.3 Opening rSeqTU from Bacterial RNA Analysis

  1. Extract the complete package to a normal writable folder. Do not run the executable from inside the ZIP.
  2. Open Bacterial RNA Analysis.exe at the package root.
  3. Choose Operons and transcription units, then select the rSeqTU card.
  4. The rSeqTU interface opens inside the same main window. Use Open Instructions to reopen this guide.
  5. Click Check R when needed. If R is absent, use Install R and complete the official Windows installer.

The application searches the Windows path, registry, Program Files and current-user program folders for Rscript.exe. Missing packages are installed automatically; packages already installed and loadable are skipped.

Navigation: You may return to the operon-method chooser or the main analysis-module dashboard only when no rSeqTU run is active. If a run is in progress, stop it and wait for shutdown to finish before navigating away.

4. Preparing Input Files and Replicate Strategy

Input Requirement Important notes
BAM file Coordinate-compatible RNA-seq alignments. One BAM is analysed per run. A matching .bai may already exist; otherwise the software creates one.
GFF/GFF3/GTF Gene annotation for the target reference. Nine-column annotation files are accepted. Gene order, identifiers and strand must be biologically correct.
FASTA Complete genomic DNA sequence. Use genomic DNA, not a CDS-only or RNA FASTA.
Result folder Writable destination for retained outputs. Use a separate folder for each sample or run to avoid mixing results.
Chromosome name Optional reference identifier. When blank, the first FASTA record and first GFF/GFF3 sequence ID are used to match the BAM reference.

4.1 File consistency checks

  • The selected BAM reference length must match the selected FASTA sequence length.

  • The selected GFF/GFF3/GTF sequence ID must describe the same chromosome or replicon.

  • Annotations outside the linear reference length, including an origin-spanning row, are removed from the cleaned rSeqTU GFF.

  • The BAM should represent a stranded RNA-seq workflow whose orientation is known.

4.2 Biological replicates

  • Run each biological replicate separately using the same FASTA, annotation and quality thresholds.

  • Do not merge treatment and control samples into one BAM for a single rSeqTU prediction.

  • For three replicates, a practical post-analysis rule is to prioritize TU boundaries reproduced in at least two runs.

  • Any merged-BAM or consensus procedure should be reported as an additional adaptation because it is not the replicate model described by the original package.

5. Analysis Parameters and Strand Awareness

Parameter Default Accepted range Purpose
Minimum mapping quality 15 0-255 Excludes alignments below the selected MAPQ threshold during pileup.
Minimum base quality 10 0-255 Excludes individual bases below the selected base-quality threshold.
Chromosome name Blank Text Selects a specific BAM/FASTA/GFF reference; blank uses the first sequence records.

5.1 Recommended use

Keep the default quality values unless the sequencing protocol, aligner settings or QC profile provides a clear reason to change them. Raising a threshold removes lower-quality evidence; lowering it retains more reads but may introduce less reliable coverage.

5.2 Strand-aware analysis

The workflow generates separate forward- and reverse-strand coverage columns and uses the annotation strand for TU prediction. The final bedGraph displays forward-strand TUs as positive values and reverse-strand TUs as negative values.

Library-strand caution: Incorrect assumptions about RNA-seq strandedness can invert or blur the biological signal. Confirm the library orientation before interpreting TU boundaries.

6. Running the Pipeline

6.1 Starting a run

  1. Select the BAM, GFF/GFF3/GTF, FASTA and result folder.
  2. Optionally enter the chromosome name and adjust the quality thresholds.
  3. Click Run pipeline.
  4. Follow the workflow cards, progress panel and live Log area.
  5. Keep the application open until the completion dialog appears.

6.2 Backend sequence

Step Backend operation
1-2 Validate inputs, detect R and verify required packages.
3 Prepare or verify the BAM index and select the matching reference.
4 Generate the QuasR QC report.
5 Extract and validate strand-specific per-base coverage.
6 Prepare the chromosome FASTA and cleaned GFF/GFF3.
7 Create rSeqTU-compatible feature matrices.
8 Run recursive feature selection and SVM prediction.
9 Export the bordered Excel workbook and final corrected bedGraph; remove the raw underscore bedGraph.
10 Create IGV Results, always copy the bedGraph, annotation and FASTA, and optionally copy the BAM with its matching BAI.
11 Verify all retained files and delete temporary coverage, feature and generated working files.

The Open result folder button remains usable during a run. After a run finishes, fails or is stopped, click Reset to clear all selected paths, restore the default mapping and base-quality values, reset workflow progress and clear the on-screen log. Reset prepares the same window for the next sample and does not delete completed result files. The Samples run this session panel is not cleared by Reset; it records the sample name, time and outcome until the application is closed.

8. Monitoring, Stopping and Recovery

8.1 Progress indicators

Workflow-card status is exact because the backend writes defined checkpoints. The percentage is an estimate, not a measurement of CPU work. Recursive feature selection may remain at 85% for many minutes before the next checkpoint.

Estimated percentage Current operation
75% Generating rSeqTU feature matrices
85% Predicting Transcription Units with the SVM
93% Finalizing the TU Excel workbook and final bedGraph
95% Creating the IGV Results folder
97% Verifying outputs and deleting intermediate files
100% All requested outputs verified

8.2 Stopping safely

Click Stop pipeline and confirm the warning. The GUI terminates the R process tree, removes files created by the cancelled run and protects the original BAM, annotation and FASTA inputs.

8.3 Completion and diagnostic logs

A completed run displays a completion dialog and notification sound. Every completed or failed run exports one full console log containing paths, thresholds, timestamps, the exact R source and command used, standard output, warnings, errors and final state. No duplicate source-code directory is created; the full console log itself contains the exact R source, configuration and execution command.

8.4 Session sample history

The Samples run this session panel lists each completed, failed or stopped run with its sample name, time and outcome. The list remains visible after Reset so the user can avoid selecting the same sample accidentally. When a BAM that already completed successfully in the current session is selected again, the software displays a confirmation warning before starting. This history is stored only in memory and is cleared automatically when the software is closed and reopened.

Retained result Purpose
<sample> QuasR QC report.pdf QuasR quality-control report.
<sample> Final TU Table.xlsx Bordered TU table; row 1 is the title, row 2 contains headers and no blank row is inserted.
<chromosome> rSeqTU clean for SVM.gff Cleaned chromosome-specific GFF used by the SVM stage.
<sample> rSeqTU full console log.txt Complete console output, settings, warnings, errors and final state.
IGV Results/<BAM>.bam
Optional		 BAM used by the analysis. Included only when Copy BAM and BAI to IGV Results is selected.
IGV Results/<BAM>.bam.bai
Optional		 Matching BAM index placed beside the BAM when the optional copy setting is selected.
IGV Results/<sample> result.bedgraph Only retained bedGraph; IGV-ready coordinates and strand sign.
IGV Results/<input annotation> Copy of the selected annotation in its original filename and format.
IGV Results/<input FASTA> Copy of the selected genomic FASTA in its original filename and format.

Viewing results in IGV

  1. Open the genomic FASTA as the reference genome.
  2. Load the GFF/GFF3 annotation as the gene track.
  3. From the IGV Results subfolder, load <sample> result.bedgraph for predicted TU intervals.
  4. If Copy BAM and BAI to IGV Results was selected, load the copied BAM together with its matching .bai index for read-level coverage. Otherwise, load the original BAM and matching index from their original location.
  5. Interpret positive bedGraph values as forward-strand TUs and negative values as reverse-strand TUs.

Generated bedGraph coordinates are zero-based and half-open, whereas GFF/GFF3 coordinates are one-based and inclusive. The converter handles this difference automatically.

10. Interpreting Results and Responsible Use

10.1 Final TU Excel workbook

Column Interpretation
TU ID Identifier assigned to the predicted Transcription Unit.
Start / End One-based genomic interval reported by the rSeqTU TU table.
Strand Forward (+) or reverse (-) annotation strand.
Confidence Model output retained from rSeqTU; values may frequently be 1 in the current package implementation.
Genes Gene identifiers grouped into the predicted TU.

10.2 Recommended review sequence

  1. Review the QuasR QC report before interpreting predictions.
  2. Inspect the final bedGraph and BAM coverage in IGV.
  3. Check gene orientation, intergenic continuity and abrupt coverage changes.
  4. Compare biological replicates run separately and prioritize reproducible boundaries.
  5. Validate important predictions with independent evidence such as RT-PCR, long-read RNA sequencing, promoter/terminator mapping or curated operon databases.

10.3 Limitations

  • Predictions are model-based and are not experimental confirmation.

  • One BAM is processed per run; replicate variance is not modelled jointly.

  • Results depend on expression under the sampled condition, sequencing depth, mapping quality and annotation accuracy.

  • Alternative promoters, internal terminators and condition-specific suboperons can create real coverage changes within a predicted TU.

  • The software should be used as a prioritization and visualization tool, not as the sole basis for clinical, regulatory or safety-critical decisions.

11. Troubleshooting

Problem Recommended action
The main suite or rSeqTU workspace does not open Keep the complete extracted package together and start only Bacterial RNA Analysis.exe. Inspect Application\Logs\launcher.log and Application\Logs\gui-startup.log. Do not launch the internal .ps1 file directly.
R is not detected Complete the official R installer, reopen the GUI and click Check R.
Chromosome selection fails Confirm that BAM, FASTA and GFF/GFF3 identifiers and reference lengths describe the same chromosome.
The run remains at 85% Check the live Log and Task Manager. Recursive feature selection can be lengthy.
A pipeline error appears Open <sample> rSeqTU full console log.txt and inspect the final error and the WARNINGS AND ERRORS section.
IGV cannot open the BAM Open the BAM and matching .bai from the same IGV Results subfolder. Confirm that the copied annotation and FASTA describe the same reference.
Two bedGraph files remain from an older version Use IGV Results/<sample> result.bedgraph. The current release removes the underscore version automatically.
Results from separate replicates disagree Review QC, strandedness, sequencing depth and condition-specific expression. Do not force a consensus without reporting the disagreement.

Reporting a reproducible run

Archive the full console log, QC PDF, final Excel workbook, cleaned SVM GFF, the IGV Results subfolder and whether BAM/BAI copying was enabled, software version and the mapping/base-quality thresholds. Record whether the chromosome was selected automatically or entered manually.
