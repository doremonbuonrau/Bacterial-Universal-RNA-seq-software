TU Architecture & Manual Curation - Instructions

Combine predicted transcript segments with gene annotation, start/RBS evidence, and terminator evidence to construct reviewable transcription-unit candidates.

Purpose

This module builds transcription-unit (TU) candidates from predicted_transcripts.tsv produced by Transcript Discovery and a matching genome annotation. It can add Prodigal translation-start/RBS evidence and import verified terminator calls.

Coverage-inferred transcript boundaries are not automatically validated promoters or terminators. The module deliberately keeps a manual curation step before curated TUs are exported.

Required inputs

  • RNA Processing result folder or explicit reference FASTA/GFF overrides.
  • Predicted transcripts TSV from Transcript Discovery.
  • Results folder.

The FASTA, annotation, and transcript coordinates must refer to the same genome assembly and contig names.

Architecture evidence

  • Prodigal RBS / translation-start evidence: optional supporting evidence generated when Prodigal is installed.
  • TransTermHP availability: records that terminator analysis is desired, but this build does not guess an external caller command.
  • Verified terminator table: optional imported TSV/CSV terminator calls used as supporting evidence.

What the manual TU review table is for

manual_tu_review.tsv is not source code and should not be merged into the live console. It is editable biological curation state. Review each proposed TU, then edit fields such as manual_assignment, locked, and notes. Use Save manual edits to preserve the table. Use Export curated TU to convert accepted rows into GFF3 and BED.

Rows whose manual assignment is reject/rejected/exclude are omitted from the curated export.

Recommended workflow

  1. Click Check environment / packages first. The live console reports the shared scientific environment plus TU-related tools such as Prodigal, Infernal/cmscan, RNAfold, TransTermHP, bedtools, and Java; optional tools may be reported as missing without blocking unrelated TU evidence.
  2. Run Transcript Discovery first and review its predicted transcript evidence.
  3. Click Scan RNA / Transcript Discovery folder and choose the completed RNA Processing or Transcript Discovery result tree. One recursive scan assigns the RNA Processing folder, predicted_transcripts.tsv, matching FASTA/GFF, optional terminator table, and a default TU result folder.
  4. If you need to enter paths, transcripts, or terminators yourself, click Manual Excel input. Pale examples appear immediately inside empty cells; type or paste real values over them and choose Use data. Optional Excel export contains only editable input sheets.
  5. Review the assigned paths and add Prodigal and/or verified terminator evidence when available.
  6. Run architecture construction.
  7. Inspect Operon and transcription units.xlsx, the manual review table, and genome-browser evidence.
  8. Edit the manual curation fields, save them, then export curated TUs. Checks, progress, and export messages stay in the live console.

Outputs

  • Operon and transcription units.xlsx with TU candidates, RBS/start evidence, terminator evidence, boundary evidence, manual-review copy, and provenance.
  • manual_tu_review.tsv for editable curation.
  • Curated TU/curated_transcription_units.gff3 and .bed after curated export.

Interpretation and troubleshooting

  • Do not call a coverage edge a validated TSS/TTS without independent evidence.
  • If the module cannot find transcripts, explicitly select the predicted_transcripts.tsv file.
  • If reference files are missing, choose the matching FASTA/GFF overrides.
  • If Prodigal or terminator evidence is unavailable, TU candidates can still be reviewed, but confidence should reflect the missing evidence layer.
