1. Overview

This operon module contains two different algorithms for predicting bacterial transcription units: rSeqTU and OpDetect.

OpDetect was published on 1 August 2025 by Rezvan Karaji and Lourdes Peña-Castillo at Memorial University of Newfoundland. The article credits Karaji for software and Peña-Castillo for conceptualization, methodology and supervision. The integrated Windows interface in Bacterial RNA Analysis was developed by Nguyen Hoang An and preserves the attribution of the original OpDetect algorithm.

OpDetect identifies whether neighbouring genes are likely to belong to the same operon by analysing RNA-seq read coverage across Gene 1, the intergenic region, and Gene 2. The original method was created by Rezvan Karaji and Lourdes Peña-Castillo at Memorial University of Newfoundland. The integrated OpDetect workspace in Bacterial RNA Analysis provides guided installation, graphical file selection, replicate handling, quality control, multi-contig support, progress monitoring, genome-browser tracks and verified result export.

Current integrated workflow: Open Bacterial RNA Analysis.exe, choose Operons and transcription units, and select OpDetect. The OpDetect workspace is shown inside the same main window. Use < Back to operon methods to compare methods or < Back to analysis modules to return to the dashboard. Do not look for or launch a separate OpDetect executable.

1.1 Main capabilities

  • Accepts a matching genomic FASTA and GFF/GFF3 annotation plus one to six single-end or paired-end RNA-seq replicates.

  • Runs fastp, HISAT2, SAMtools and BEDtools automatically inside a dedicated WSL2 Ubuntu environment.

  • Uses the ten supplied OpDetect model folds and reports probability, model variability and replicate-arrangement support.

  • Exports two formatted Excel workbooks, top-level fastp HTML reports, cleanly named BAM/BAI files, a signed predicted-operon bedGraph, the selected FASTA and annotation inside the IGV folder, and one complete Word run report.

  • Keeps the Windows result folder concise. Detailed machine information, parameters, QC summaries, timings, the generated orchestration code and the complete console record are preserved in the run report and persistent log.

  • Prints the generated pipeline script, configuration, sample sheet, and Python helper source in the live console and persistent live_run.log without creating a duplicate code folder.

  • Supports safe stopping, one-click reset for a new analysis, result recovery and selective environment removal through the main suite maintenance utility.

2. Scientific Basis and Unique Advantages

2.1 Direct RNA-seq signal representation

Instead of relying mainly on species-specific databases or hand-engineered comparative-genomics features, OpDetect uses per-nucleotide RNA-seq coverage as its predictive signal. For each adjacent same-direction gene pair, coverage over Gene 1, the intergenic region and Gene 2 is proportionally resampled into a 150-position representation with three channels. Up to six RNA-seq samples provide the sample dimension used by the neural network.

Input dimension Meaning
150 positions Proportionally resampled Gene 1 + intergenic region + Gene 2 signal
6 sample channels RNA-seq samples or replicate-channel arrangements
3 regional channels Gene 1, intergenic region and Gene 2, with other regions zero-padded

2.2 CNN–LSTM architecture

  • The convolutional layer captures local spatial coverage patterns across the gene–intergenic–gene signal.

  • The LSTM captures sequential dependencies across the resampled nucleotide signal.

  • A self-attention layer emphasizes informative positions before the final two-class probability output.

  • Ten trained folds are combined to reduce dependence on one training split.

2.3 What makes OpDetect distinctive

  • Species-agnostic design: it was intended to generalize beyond a single target bacterium.

  • Broad applicability: the main predictive features are RNA-seq coverage and genome annotation rather than restricted external databases.

  • Cleaner supervision: training used experimentally verified operons and conservative non-operon labels, while unknown pairs were excluded.

  • Independent-organism validation: organisms used for evaluation were separated from those used for training to reduce data leakage.

  • Cross-domain evidence: the published evaluation included several bacterial species and Caenorhabditis elegans, an operon-containing eukaryote.

3. Performance Evidence and Comparison

The values below describe the published OpDetect research evaluation. They do not guarantee the same performance for every organism, library preparation, sequencing depth or annotation.

3.1 Ten-fold cross-validation results

Metric Published value
Recall 89.17%
F1-score 89.71%
Accuracy 90.37%
AUROC 0.892

3.2 Independent validation comparison

Method Average AUROC across seven validation bacteria
Operon-mapper 0.70 ± 0.04
Rockhopper 0.63 ± 0.11
Operon Finder 0.83 ± 0.10
OperonSEQer 0.81 ± 0.07
OpDetect 0.93 ± 0.04

In the paper, OpDetect achieved the highest average F1-score and average AUROC among the compared methods. Its performance distribution also showed less spread across organisms, suggesting more stable generalization in the evaluated datasets.

3.3 Noncontiguous-operon case study

  • For 31 gene pairs separated by an intergenic region within known noncontiguous operons, OpDetect identified 28 pairs (90%).

  • For 18 pairs that jumped over an antisense gene, it identified 5 pairs (28%).

  • This demonstrates useful signal detection but also highlights a major limitation for complex noncontiguous operon structures.

Interpretation: Published benchmark labels are incomplete because only experimentally confirmed relationships were used. A prediction counted as a false positive may sometimes represent a real but not yet experimentally confirmed operon.

4. System Requirements and Installation

4.1 Recommended environment

  • A 64-bit Windows 10 or Windows 11 computer with hardware virtualization enabled.

  • Administrator permission during the first WSL installation or Windows-feature change.

  • At least 16 GB RAM recommended; 20 GB or more free disk space is advisable for WSL, BAM files, coverage and results.

  • Internet access during initial setup to install Ubuntu packages and clone the official OpDetect repository.

  • A writable result folder on a local or external Windows drive.

4.3 Opening and preparing OpDetect

  1. Extract the complete Bacterial RNA Analysis package to a normal writable folder. Do not run it from inside the ZIP.
  2. Open Bacterial RNA Analysis.exe, choose Operons and transcription units, and select OpDetect.
  3. In the embedded OpDetect status panel, click Readiness check.
  4. When an item is missing or outdated, click Install or repair. Allow the setup to create or update WSL2, Ubuntu, Miniforge and the opdetect-pipeline environment as required.
  5. When setup finishes, reopen the main suite if Windows requests it, return to OpDetect and repeat Readiness check. All required status items should report Ready.
  6. Use Open instructions to reopen this guide. After a run, select RESET NEW RUN to clear the current files, samples, settings, progress and on-screen log while keeping readiness and current-session history.
Navigation: Use < Back to operon methods or < Back to analysis modules only when no OpDetect run is active. The main suite remains the host application throughout the session.

5. Preparing Input Files and Replicates

Input Requirement Important notes
Reference FASTA Complete genomic DNA sequence May contain one or more chromosomes, plasmids or contigs. Use genomic DNA, not CDS-only FASTA.
GFF/GFF3/GTF Matching gene or CDS annotation Column 1 sequence IDs must match the first token of the FASTA headers. Nine-column GTF annotations are also accepted.
RNA-seq FASTQ One to six biological replicates Use libraries from one biological condition per project. For explicit paired-end import, choose mate 1 first and mate 2 second. Their filenames may use any convention.
Result folder Writable Windows folder A timestamped project subfolder is created automatically.

5.1 Biological-replicate design

  • Add each biological replicate separately; do not merge FASTQ files before analysis.

  • Do not place control and treatment samples in the same project. Run each condition separately.

  • Technical replicates should normally be combined or handled according to the experimental design before biological interpretation.

  • Coverage and QC are generated per replicate. When at least two biological replicates are supplied, Pearson and Spearman matrices are exported together in Replicate correlations.xlsx.

  • When fewer than six samples are supplied, the Windows extension creates balanced channel arrangements and combines predictions. This is an interface extension, not an original paper procedure.

5.2 Read naming and pairing

  • Use Add paired-end replicate and select mate 1 followed by mate 2. The files are accepted as a pair because you selected them together; their names are not checked. Folder scanning alone uses common R1/R2 or _1/_2 patterns.

  • Use Add single-end replicate(s) only for genuinely single-end data.

  • A sample name should be unique within the project and should describe the replicate clearly, for example Control-1 or ABS-2.

Scientific caution: More replicates can reveal disagreement and improve confidence assessment, but replicate number cannot compensate for poor mapping, incorrect annotation, mixed conditions or inadequate sequencing depth.

6. Configuring Analysis Parameters

Parameter Default Purpose and guidance
CPU threads Suggested from detected hardware Controls parallel trimming, mapping and sorting. Please leave some free resources available for Windows.
Prediction threshold 0.50 Pairs at or above the selected probability are positive. Higher values are more conservative; lower values increase sensitivity.
Annotation feature CDS Choose the feature that best represents protein-coding genes in the supplied GFF3.
Replicon topology Auto Use Circular for complete circular chromosomes/plasmids; Linear for scaffolds or incomplete contigs.
Consensus support 0.60 in robust grouping A robust edge must be supported by a sufficient fraction of model/arrangement predictions.

6.1 Threshold interpretation

The original OpDetect paper used 0.50 as the default confidence threshold. A probability is model confidence, not a biological probability established by experiment. Borderline pairs should be reviewed together with coverage continuity, gene orientation, replicate agreement and known promoters or terminators.

6.2 Circular and linear references

  • Circular topology permits a last-to-first gene pair and can represent operons crossing the coordinate origin.

  • Linear topology never joins the final gene to the first gene.

  • Auto is appropriate for complete named chromosomes and plasmids but should be checked carefully for draft assemblies.

6.3 Multi-contig references

Each contig is integrated separately. Gene pairing never crosses from one contig to another. FASTA and GFF/GFF3 sequence identifiers must match exactly, and topology should reflect whether each record is a complete replicon or a linear assembly fragment.

7. Running the Pipeline

7.1 Starting and monitoring a run

1. Select the reference FASTA and matching GFF/GFF3.

2. Confirm or edit the project/condition name.

3. Add all biological replicates for that condition.

4. Choose CPU threads, threshold, annotation feature and topology.

5. Select the result parent folder and click Run OpDetect.

6. Follow the ten task rows, progress bar and live console panel. The live console and live_run.log include the generated pipeline code, commands and program output. Use Stop Run for a controlled cancellation. After completion, click RESET NEW RUN before selecting the next project; readiness remains unchanged.

8.1 Viewing results in IGV

  1. Open the copied FASTA from the IGV folder as the IGV reference genome.
  2. Load the copied GFF, GFF3, or GTF annotation from the IGV folder as the gene track.
  3. Load IGV/<project> predicted operons.bedgraph to display the predicted operon intervals. Positive values are forward-strand predictions and negative values are reverse-strand predictions.
  4. If Copy BAM and BAI to IGV folder was selected, load each copied IGV/<replicate>.bam file and keep its matching <replicate>.bam.bai beside it. Otherwise, load the BAM/BAI from the internal results or another retained alignment location.
  5. Open <replicate> fastp.html from the top-level result folder in a web browser to review read quality and filtering before interpreting the predictions.
Coordinates: BED and bedGraph use zero-based, half-open coordinates. GFF/GFF3 uses one-based inclusive coordinates. The converter handles this difference automatically; do not manually shift generated tracks.

9. Interpreting Replicate-Aware Results

9.1 Important prediction columns

Column concept Interpretation
Mean probability Average OpDetect model score across the ten folds and replicate-channel arrangements. It is not a statistical p-value and is not a guaranteed probability that the biological prediction is correct.
Model-fold variability Variation caused by the ten trained OpDetect folds.
Replicate-order variability Variation caused by alternate balanced channel arrangements when fewer than six replicates are available.
Support fraction Fraction of model/arrangement predictions supporting the pair as an operon.
Prediction Thresholded mean-probability classification.
Robust prediction More conservative classification requiring probability and consensus support.

9.2 Recommended review sequence

1. Check fastp and HISAT2 QC before interpreting any operon predictions.

2. Review replicate correlations. Investigate low-agreement replicates rather than automatically accepting the consensus.

3. Open the signed predicted-operon bedGraph, the sample-named BAM/BAI files, the FASTA, and the matching annotation in IGV.

4. Inspect continuity across gene bodies and intergenic regions, abrupt coverage changes and strand-consistent annotation.

5. Prioritize robust predictions with strong support and low variability; treat borderline pairs as hypotheses.

6. Confirm biologically important operons with independent evidence such as RT-PCR, long-read RNA sequencing, promoter/terminator mapping or curated databases.

9.3 Conditions and biological context

An operon may be active only under particular conditions. Lack of continuous coverage in one experiment does not prove that genes can never be co-transcribed, and strong bulk coverage can hide alternative promoters, terminators or subpopulation-specific expression. Run biologically distinct conditions as separate projects and compare their results.

10. Limitations and Responsible Use

  • Predictions are model-based and are not experimental confirmation of an operon.

  • The model depends on RNA-seq depth, mapping quality, annotation accuracy and whether the investigated condition expresses the relevant genes.

  • The original input architecture has six RNA-seq sample channels. The Windows replicate-arrangement strategy for fewer than six samples is an added consensus method and has not been independently benchmarked in the published OpDetect paper.

  • The default 0.50 threshold may not be optimal for every organism or special operon structure.

  • Promoter and terminator data are not direct model features. The paper identifies their inclusion as a future improvement.

  • Published operon labels are incomplete. Apparent false positives can include real relationships that have not yet been experimentally verified.

  • Complex noncontiguous operons remain difficult: the published antisense-jumping case study detected only 5 of 18 such gene pairs.

  • Grouping positive adjacent pairs into multi-gene candidate operons is a Windows post-processing step. Errors in one edge can split or join a candidate group.

  • Species-agnostic performance means broad demonstrated applicability, not guaranteed accuracy for every bacterium, archaeon, eukaryote or draft assembly.

  • Multi-contig and circular-origin handling require correct sequence identifiers and topology. Wrong topology can create an artificial last-to-first pair.

  • CPU-only TensorFlow works but may be slower. CUDA warnings can be ignored when the run completes in CPU mode.

  • The tool should not be used as the sole basis for clinical, regulatory or safety-critical decisions.

Best practice: Use OpDetect as a prioritization and visualization tool. Archive the run report, inspect QC and tracks, report the selected threshold, number of replicates and software version, and validate key findings independently.

11. Troubleshooting and Environment Removal

Problem Recommended action
The main suite or OpDetect workspace does not open Keep the complete extracted package together and start only Bacterial RNA Analysis.exe. Inspect Application\Logs\launcher.log and Application\Logs\gui-startup.log. Do not launch the internal PowerShell script directly.
Readiness status is not Ready Run Readiness check, then Install or repair. When setup finishes, return to the embedded OpDetect workspace and repeat the check.
Paired-end files were selected incorrectly Use Add paired-end, choose mate 1 first and mate 2 second, and ensure they are different files. Their filenames may use any convention.
FASTA and GFF IDs disagree Make column 1 of GFF/GFF3 match the first FASTA-header token exactly.
Run stops during models Run Readiness check and use Install or repair if the model runtime is incomplete. Then rerun the same configuration and result location so verified checkpoints can be reused safely.
Linux finished but Windows export was not verified Keep the same result location, inspect live_run.log, confirm that the Windows folder is writable and rerun the same configuration. Verified checkpoints are reused where safe. Advanced recovery scripts remain under the internal OpDetect App folder and should be used only after reviewing the log.
Need files from an older run Open the original Windows result location. The verified export contains the Excel tables, operon bedGraph, fastp HTML, sample-named BAM/BAI files, archived FASTA/annotation inputs when available, Word report, persistent log containing the complete code and command trace.
The interface still says Running after Linux finishes Wait for Windows export verification. The embedded interface completes only after the 100% marker and required exported files are confirmed. If it remains unchanged, inspect live_run.log and use Stop Run only after confirming that no export is still active.
Correlation files are not visible They are generated only for runs with at least two biological replicates. Open Replicate correlations.xlsx in the top-level result folder; Pearson and Spearman are separate worksheets.

11.1 Removing the OpDetect environment

  • From the main Bacterial RNA Analysis environment page, select Uninstall environments, or open Application\Maintenance\Uninstall Bacterial RNA Analysis.bat.

  • Select OpDetect Conda environment (opdetect-pipeline) to remove only the OpDetect analysis environment while keeping the rest of the suite.

  • Select Entire OpDetect Miniforge folder (~/miniforge3) only when no other software uses that Miniforge installation.

  • Do not unregister the complete WSL distribution unless you intend to delete every Linux file and environment stored in it.

  • Analysis results saved outside the extracted application folder and the original FASTQ, FASTA and annotation files are not removed by the environment-only choices.

Destructive action: Removing the complete Miniforge folder or unregistering a WSL distribution can permanently delete environments and unexported Linux files. Verify that important results have been copied to a Windows result folder before confirming.
