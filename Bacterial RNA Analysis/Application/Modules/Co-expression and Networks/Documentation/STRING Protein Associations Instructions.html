STRING Protein Associations - Instructions

Add STRING physical or functional association evidence to a bacterial gene set, with optional comparison to an expression-derived network.

Purpose

This module queries STRING v12 for protein associations. It can retrieve either physical associations or the broader functional network and can compare STRING-supported pairs with an existing WGCNA, CEMiTool, or GENIE3-style edge table.

STRING association does not automatically mean direct regulation. Functional edges can combine several evidence channels; physical mode is narrower but still should be interpreted as database evidence.

Required inputs

  • Gene / protein list: one identifier per line or a TSV, CSV, TXT, or XLSX table. The identifier column is detected automatically.
  • STRING organism: choose a common organism or type a numeric NCBI taxonomy ID. The ID must occur in STRING's supported-organism catalog; the software validates it before retrieval.
  • Network type: physical or functional.
  • Minimum STRING score: an integer from 0 to 1000. Higher values retain fewer, stronger-evidence associations; lower values increase coverage and density but admit weaker associations. The default 700 is a high-confidence starting point.
  • Results folder.

An existing expression-edge table is optional. It should contain source and target columns so the software can create a combined evidence table. Use the circular ? beside the score for the same threshold guidance inside the application.

Recommended workflow

  1. Click Scan DE / functional results folder and select the completed Differential Expression or Functional Enrichment result tree. The recursive scan assigns a gene/protein list, optional expression-network edges, a nearby GFF or gene-to-protein/UniProt bridge when available, a taxonomy-ID text file, and a default result location.
  2. If files are not available yet, click Manual Excel input. Pale examples are visible immediately inside empty cells and remain display-only; type or paste real identifiers over them and choose Use data. Export workbook is optional and does not create separate example sheets.
  3. Choose or enter the exact bacterial taxonomy ID and click Validate organism. Taxonomy is never guessed or replaced with a related species silently.
  4. Choose physical associations when you specifically want protein-interaction evidence; choose functional associations when pathway/co-function evidence is also useful.
  5. Use a high required score for conservative interpretation. Add extra STRING nodes only when biologically justified.
  6. Run and inspect unmapped identifiers before interpreting the network. Environment checks, retrieval progress, and full errors appear in the live console. Install or repair opens the existing installer console for elevation and prompts; check the environment again when it finishes.

Outputs

STRING PPI interactive.html is a self-contained, double-clickable network workspace with the same linked spreadsheet, filtering, appearance controls, and export design used by co-expression analysis. The workbook contains STRING edges, mapped/unmapped identifiers, network summary, optional combined expression + STRING evidence, and provenance. GraphML is retained for Cytoscape/Gephi and other network tools, while raw mapping/network responses are cached under Intermediate files/STRING cache.

Interpretation

  • Mapped query means STRING recognized the supplied identifier for the selected taxonomy.
  • Combined score is a STRING confidence measure, not an RNA-seq effect size.
  • Supporting layers = 2 indicates a pair found both in the supplied expression network and STRING; it is stronger multi-source support, not proof of causality.
  • Large numbers of unmapped genes usually indicate wrong taxonomy or an identifier mismatch.

Troubleshooting

  • Unsupported organism: a valid NCBI taxonomy ID is not necessarily represented in STRING. Choose a supported strain from the list or verify the exact organism ID; do not substitute a related organism unless that is a deliberate scientific decision.
  • Backend exited with code 2: the live console displays the backend's detailed validation or service message instead of only the exit code.
  • Confirm internet access if a supported organism validates but API retrieval still fails.
  • CVV72_RS or other locus tags do not map: keep the matching RNA Processing GFF inside the same project tree. The software finds it automatically and retries its explicit protein_id/UniProt links. If no matching annotation is present, select it in Identifier aliases.
  • If a network becomes unreadably dense, raise the required score and avoid adding extra nodes.

Identifiers and latest results

Use latest results loads the last DE significant-gene list and tries to pair the retained RNA Processing annotation. A valid organism does not guarantee that STRING recognizes locus tags directly. The backend searches nearby project folders for the matching GFF or gene-to-protein/UniProt table, then retries only verified links. The search never crosses into a whole mounted drive. The mapping audit retains input IDs; unmatched and ambiguous aliases are reported. Only resolved STRING identifiers are used for network requests.

Hover over the score help circle for the range and tradeoff. Higher confidence cannot fix an identifier mismatch.
