Scope

RNA-seq processing begins with reads and ends with validated analysis-ready BAM/BAI, raw counts, coverage, normalized reference files, QC, and provenance. Differential expression performs replicated statistical comparison. Functional enrichment and co-expression networks coordinates enrichment and expression-network interpretation from the same DE handoff and annotation source. Operons and transcription units provides the integrated rSeqTU and OpDetect workflows.

Coordination does not erase scientific distinctions. Enrichment uses DE statistics and gene sets, while co-expression uses normalized profiles across independent samples. Raw counts are not replaced by TPM or FPKM for differential-expression testing, co-expression is not labelled as confirmed regulation, and short-read and long-read BAM families are not merged.

Custom bacterial functional mappings and exported network tables can include pathway, regulon, orthology, or STRING-derived annotations prepared by the user.

Installation and environment

Windows

  1. Right-click the downloaded ZIP, open Properties, select Unblock if present, and extract it to a writable local folder.
  2. Open Bacterial RNA Analysis.exe.
  3. Use Application/Maintenance/Install or Repair.bat when WSL2, Ubuntu, Miniforge, or the core processing tools are not ready.
  4. Inside Functional Enrichment and Co-expression Networks, select Install or update once to create or update the shared prok-rnaseq-downstream environment. The same environment contains online annotation, clusterProfiler, fgsea, topGO, CEMiTool, WGCNA, GENIE3, plotting, Excel, and HTML-report dependencies; there is no second network environment.
If startup fails, inspect Application/Logs/gui-startup.log and Application/Logs/launcher.log.
Dorado is optional and applies only to raw ONT POD5. Supplied FASTQ or unaligned BAM is already basecalled. See Dorado SUP setup.md.

Linux

Run bash App/environment/setup_linux.sh --analysis-type short, --analysis-type long, or --analysis-type both, then run the matching environment check. The backend supports Ubuntu and Debian automated setup.

Samples, conditions, biological replicates, and technical runs

The processing module accepts multiple conditions in the same project. Use Condition for new rows to switch between Control, Treatment, time points, strains, doses, mutants, or other groups before adding their read files. Replicate numbering is independent within each condition.

Biological replicate: use a different Sample ID, such as control_1, control_2, and control_3. The Condition may be the same.
Technical run: repeat the same Sample ID on multiple rows. Each run receives its own read group and is aligned separately; BAMs are then merged only within that Sample ID.
  • Rows sharing an ID must share the same condition.
  • Short technical runs cannot mix single-end and paired-end layouts.
  • In a combined project, a sample can use separate rows for its short and long inputs.
  • Short and long BAMs always remain separate, even when the Sample ID matches.
  • Short-read and long-read strand settings are also separate, so a dUTP convention is not imposed on ONT or PacBio.
  • The software warns when later differential expression would have too few biological replicates, but it still allows valid BAM export.

Choosing methods

The methods page is one continuous top-to-bottom workflow. Short mode shows short-read QC and alignment before counting and coverage. Long mode shows basecalling, QC, and alignment before counting and coverage. Both mode shows short- and long-read methods in sequence, followed by the common export settings. No separate method/export panels or method-session tabs are used.

Short-read QC

Default FastQC + fastp + MultiQC gives raw/post-cleaning evidence and automatic paired-end adapter detection. Choose Cutadapt when the exact adapter is known. Choose QC only only when the provider already cleaned the files.

Short-read alignment

Bowtie2 sensitive end-to-end is the initial bacterial setting. Select Guided tool options to choose default, very-fast, fast, sensitive, or very-sensitive; switch between end-to-end and local alignment; and browse common Bowtie2 settings. The dual mode also creates an independent BWA-MEM2 BAM. The two BAMs are compared in QC and never merged. HISAT2 is reserved mainly for reproducing an older no-splice workflow.

Guided command-line options

The Guided tool options dialog gives every external processing command a page with Use checkboxes, drop-downs, validated values, plain-language descriptions, workflow-owned argument warnings, a bundled offline manual, and an effective-argument preview. Free-form custom flags are intentionally not exposed. The project configuration and provenance logs preserve the structured selections and exact effective commands.

Long-read QC and alignment

NanoPlot provides direct read-length/quality evidence; LongQC adds complementary reference-free diagnostics. Minimap2 is the primary platform-aware mapper. Winnowmap2 can audit repetitive or duplicated loci.

Neural basecalling

Dorado SUP is the only accuracy-first AI component. It converts ONT POD5 electrical signal into nucleotide calls using a chemistry-matched neural model. It is irrelevant when FASTQ or unaligned BAM is already supplied.

Counts

featureCounts is the clean default and supplies the conservative integer matrix used by later DESeq2 or edgeR workflows. FADU is a separate optional prokaryotic overlap audit for short-read fragments; its fractional values are not merged into the primary matrix. Missing or failed FADU auditing is recorded as a warning and does not stop or invalidate the featureCounts export. HTSeq remains available for company-workflow reproduction.

Coverage

The recommended compact option writes CPM-normalized BigWig only: one track for unstranded data or transcript-plus and transcript-minus tracks for a stranded library. This reduces as many as 12 coverage files per sample to one or two. The comprehensive raw+CPM BigWig+bedGraph option remains available when every representation is explicitly required.

Integrated downstream analysis modules

Differential Expression and Functional Enrichment and Biological Networks open as integrated pages inside the main Bacterial RNA Analysis window. The functional workspace coordinates GO enrichment, co-expression/regulatory inference, pathway-database enrichment, and STRING PPI without separate home-page modules.

Excel-first organized output: choose a parent result location and the software creates an engine-specific DE folder or Functional enrichment and co-expression analysis. Each completed analysis retains its verified workbook and offline interactive report; figures, tracks, logs, and lossless handoff files are grouped separately.

Differential expression

Input is a raw integer gene-count matrix plus one metadata row per biological sample. edgeR quasi-likelihood is the recommended default; DESeq2 and limma-voom are also available. Every compared group requires at least three biological samples, and the backend rejects a rank-deficient condition/batch design. The configurable Volcano and Circos remain the canonical views; the improved MA and paper-guided diagnostics share the same annotated spreadsheet in both directions.

Functional enrichment and biological networks

Section 1 loads the DE result, normalized expression matrix, sample metadata, optional regulator list, mapping, and universe together. Offline mapping is reused directly; online annotation unions the enrichment and expression gene IDs and runs once. Section 3 selects clusterProfiler, fgsea, or topGO and keeps optional gene/gene-set details behind its local checkbox. Section 4 selects CEMiTool, WGCNA, or GENIE3 and keeps optional module/edge/regulatory details behind its local checkbox.

The action row enables online KEGG and STRING settings beside the shared run controls. Run all analyses uses the same selected genes and tested-gene universe for GO, co-expression, pathway enrichment, and PPI, then writes one verified workbook and one linked offline HTML report. Common organism entries remain searchable, while adjacent buttons open the official KEGG or STRING organism resources when another code is needed; no placeholder Other entry is shown.

Parameter guide explains the analysis families together, and Guided package options exposes documented package functions. The combined interactive HTML presents enrichment, co-expression, pathway, and STRING plots in one Analysis / visualization selector and uses curated linked result sheets.

Publication controls: The unified linked interactive workspace retains plot-specific appearance, typography, biological-label visibility, hover, pan, selection, and export controls.
Use the Instructions button in the combined functional module for the complete input, parameter, run, and result guide.

Run, safe stop, resume, and reset

The GUI writes a transparent rnaseq_project.json. Before a run, the numbered stage table shows the selected mode's complete plan as Pending without requiring a grid scrollbar. During a run, the active row becomes Running, completed rows become Finished, and a failed or stopped row is marked Error or Stopped. The backend records every command before it starts and updates .rnaseq_suite/state.json for the progress display.

  • Safe stop creates a stop request. The active external command may finish to avoid a truncated BAM.
  • Resume is automatic when the same configuration hash and expected checkpoint outputs are present.
  • A changed method, input, reference, or parameter changes the hash and prevents unsafe checkpoint reuse.
  • Reset project clears the current project, returns to Read type, and keeps the verified Linux/package readiness result. It also retains the current-session list and totals of completed projects and biological samples.
  • Closing the GUI does not kill an active Linux process. Reopen the same output folder to inspect logs.

Before accepting a run

  1. Open MultiQC and compare raw versus cleaned reads.
  2. Review mapping percentage and contig distribution in the SAMtools reports.
  3. Resolve any strand contradiction with the library provider.
  4. Inspect a few known expressed and non-expressed loci in IGV.
  5. Compare primary and alternative aligners at repeats if dual mode was used.
  6. Confirm gene IDs in gene_metadata.tsv and column names in the raw matrix.
  7. Verify checksums after copying the export.

A completed command is not automatically a scientifically acceptable sample. QC evidence and experimental records remain essential.

Common questions

Why not run nf-core/rnaseq directly?

It is excellent reproducible engineering and inspired validation, resume, MultiQC, version capture, and output organization. The suite uses a bacterial-specific unspliced method set, adds long reads/POD5 and FADU, and presents the decisions in a desktop wizard.

Why is AI not used for alignment?

No selected general neural aligner has stronger task-matched validation than the established bacterial mappers here. AI is used only for raw ONT signal decoding, where Dorado neural models directly address the input.

Can short and long BAMs be combined?

No. Their error models, read lengths, and statistical meanings differ. They are linked by Sample ID but exported separately.

Can I remove the work folder?

After the run is complete, the analysis-ready export is backed up, and checksums are verified. Keeping work and state permits faster resume.

Specialized plot appearance

Specialized plots automatically fit the visible plotting panel so enrichment X axes remain inside the panel. In network views, Appearance provides one color picker per node legend group and a separate Connection lines color picker. The selected colors update the live graph and its image export.
