Purpose and boundaries

This module starts with bacterial sequencing reads and produces validated, analysis-ready files. It performs reference checks, read QC or basecalling, bacterial alignment, BAM sorting and indexing, strand auditing, raw gene counting, coverage generation, and checksum-verifiable provenance logging.

This module does not perform differential-expression testing. It prepares raw integer counts and metadata for the separate Differential Expression module. Short-read and long-read BAM families remain separate because their error models and biological meanings differ.

For suite-wide navigation, downstream-module handoff, operon prediction, maintenance, and uninstall information, return to the first page and open the overall software guide.

Open the processing module

  1. Start Bacterial RNA Analysis.exe.
  2. Select RNA-seq processing on the first page.
  3. Read the module summary and select Open RNA-seq processing.
  4. Use Open guide on the top action line to reopen this module-specific guide.

2. Linux/WSL environment

Bioinformatics commands run in Linux. On Windows, the module uses WSL2. This page appears immediately after read-type selection because environment setup depends on whether the project uses short reads, long reads, or both—not on sample filenames or replicate metadata. Select Check environment for read type before adding inputs.

  • Use Install or repair core in the module. The selected read type is passed to the installer and verified after setup.
  • The short-read check verifies short-read QC and aligners; the long-read check verifies long-read QC and aligners; Both verifies both families.
  • FADU, LongQC, and Dorado remain optional and are reported separately.
  • Dorado is optional and applies only to raw ONT POD5.
  • The exact selected WSL distribution and tool versions are recorded with the run.

3. Inputs and biological replicates

Project files

  • Bacterial reference genome in FASTA format.
  • Matching GFF3 or GTF annotation with compatible sequence identifiers.
  • A writable results folder and a clear project name.

Sample table and experimental conditions

One RNA-seq processing project may contain any number of biological conditions, including Control versus Treatment, multiple doses, time points, strains, mutants, or environmental conditions. Choose or type a value in Condition for new rows before adding files. Newly added samples receive that condition automatically, and replicate numbering starts independently within each condition.

Each biological sample needs a unique Sample ID, condition, replicate number, and the applicable read files. Batch is optional. For example, use control_1, control_2, and control_3 for Control, then switch the condition selector to Treatment and add treatment_1, treatment_2, and treatment_3. Repeat the same Sample ID only for technical runs or matched short/long modalities from the same biological sample; rows sharing an ID must also share the same condition.

Recommended: include at least three independent biological replicates in every condition when the data will later be used for differential expression. Two are accepted as a minimum, but uncertainty is substantially higher.

Import actions

  • Add paired-end: select mate 1 and mate 2 explicitly; arbitrary filenames are accepted.
  • Add single-end FASTQ(s): creates one row per selected file.
  • Scan FASTQ folder: automatically infers pairs using common naming patterns.
  • Add long FASTQ/BAM or Add ONT POD5 folder: use the readable platform selector for Oxford Nanopore or PacBio.

4. Read methods and analysis-ready export on one page

The applicable settings are arranged from top to bottom as one continuous workflow. Read-processing methods appear first; counting, coverage, the modality note, and strict strand-agreement checking follow immediately below. There are no separate sessions, cards, columns, or method/export panels.

Short mode shows short-read QC/cleaning, bacterial alignment, strand, and optional adapter fields. Long mode shows basecalling choice, long-read QC, bacterial alignment, strand, filtering, and Dorado fields. Both mode shows both groups in the same compact sequence before the shared export settings.

Recommended defaults

  • Short-read QC: FastQC + fastp + MultiQC.
  • Short-read alignment: Bowtie2 sensitive end-to-end primary with optional BWA-MEM2 audit.
  • Long-read QC: NanoPlot + LongQC when available.
  • Long-read alignment: Minimap2 primary with optional Winnowmap2 repeat audit.
  • Counts: featureCounts raw integer matrix, with FADU as a separate optional overlap audit when installed. If FADU is absent or its audit fails, the featureCounts matrix is retained, the skip is recorded, and the pipeline continues.
  • Coverage: raw and CPM strand-aware tracks when library orientation is known.

Focusing or opening a method selector updates the definition, best use, AI status, required commands, advantages, and limitations on the right side.

Guided command-line tools

Select Guided tool options to choose Bowtie2 preset and local/end-to-end mode and to browse common settings for every external processing command. Use checkboxes, drop-downs, and validated fields; each page explains workflow-owned inputs and opens a bundled offline manual. Free-form custom flags are intentionally not exposed. Bowtie2 no longer receives a hidden very-sensitive preset. The active project JSON and provenance logs record every structured setting and exact effective command.

5. Review and run

The final page summarizes inputs and methods, shows every planned stage, and provides a live console. Select Run analysis in the lower-right footer to validate the project and start the pipeline. Use Open log file or Open log folder beside the live console whenever detailed diagnostics are needed.

  • Safe stop requests a controlled stop; the active external command may finish to avoid a damaged BAM.
  • Compatible completed stages are resumed using configuration hashes and expected outputs.
  • An incomplete earlier run can reuse the same folder safely; initialization records are refreshed when no completed result manifest exists.
  • A completed run with a different configuration still requires a new output folder to prevent result mixing.

Commands, complete code trace, and persistent logs

The persistent pipeline.log preserves the active project configuration, selected methods, package versions, input/output paths, exact execution commands, and the complete line-numbered contents of the Windows GUI, Windows WSL runner, Linux launcher, and every packaged Python source file used. Each source file also includes its SHA-256 hash and byte size, allowing the executed implementation to be inspected directly and verified against the installed copy. The live console displays only the most recent 512 KiB so a large audit log cannot freeze the interface; select Open log file for the complete record.

Compiled third-party programs cannot expose their original source at runtime. The suite records executable hashes and one bounded package identity row containing version, build, channel, license, dependencies, binary/upstream URLs, package hashes, and the SHA-256 of the complete original metadata record. Conda installation file inventories are excluded because they are not source code or generated analysis code.

Troubleshooting

  • Check that FASTA and annotation sequence identifiers match.
  • Confirm paired files were added through the paired-end action or both mate columns are populated.
  • Choose the read type first, then use the environment checker before entering sample information.
  • Review Application/Logs and the project run log when a command fails.
  • Inspect mapping, strand, and count-table identifiers before accepting the result.

See Troubleshooting.md, Output files.md, and Dorado SUP setup.md for additional details.

Choose the next analysis after a successful run

When RNA-seq processing finishes successfully, the suite asks what you want to do next. You can remain on the processing page to inspect the console and outputs, or move directly to one of the three downstream modules.

  • Differential expression is the recommended next step. The latest raw count matrix, sample metadata, and available gene coordinates are loaded automatically.
  • GO, enrichment and pathways opens the functional-interpretation module. It requires a completed differential-expression table or an external ranked gene list.
  • Co-expression and networks opens the network module. It requires normalized expression data and enough independent samples for reliable network estimation.
  • Stay in RNA-seq processing keeps the completed project open for review.

The choice does not move or delete the RNA-seq results. The analysis-ready export remains available to every module through the suite’s shared result handoff.

RNA-seq Processing Module Guide

Existing WSL distribution recovery

The installer normalizes hidden characters in WSL distribution names and prefers the default WSL distribution. A listed distribution is not rejected merely because a short cold-start probe is inconclusive; the complete setup command is attempted and can fall back to the default distribution. The module does not install a duplicate Ubuntu while Windows still lists an existing distribution.

Bowtie2 + HISAT2 dual alignment

Runs both aligners independently on the same cleaned short reads. Both BAM/BAI sets are retained. When raw gene counting is enabled, Counts & Annotation.xlsx contains separate Bowtie2 Raw Counts and HISAT2 Raw Counts sheets. Do not merge the two matrices or treat them as biological replicates.
